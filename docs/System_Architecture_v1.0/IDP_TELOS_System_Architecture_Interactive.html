02 · 核心模块与内部组成

这五个模块是平级独立的运行单元，EER 因职责不同承担企业任务的持久执行权威，但不是其他模块的启动前置条件。

IDP Workspace

独立企业应用平台，不是简单 AI 聊天 UI

App Shell、App Registry、H5 App Runtime、App Bridge SDK、Work Context、Work Inbox、Action Contract、审批与人机协作。

状态与权威：工作空间、应用安装配置、界面与协作状态；不直接作为订单或库存最终权威。

IDP HOST

独立 Agent Hosting & Coordination

Agent Definition/Run、Session、Agent/Skill Registry、Model Router、Harness、工具协调、A2A；可独立接模型与本地存储。

状态与权威：Agent 会话、推理与运行状态；不接管 EER 的任务 Checkpoint。

IDP EER

独立可靠执行引擎 / Execution Runtime

Goal/Task/Plan/Action、Actor / Validator / Planner / Executor / Verifier、Checkpoint、恢复、幂等、Outbox/Inbox、补偿、审批、核验与证据。

状态与权威：企业执行流程与 Checkpoint 的权威状态；业务事务最终仍由领域系统提交。

IDP CMI

独立 Context, Memory & Knowledge Infrastructure

ContextResolver、ContextPackage、记忆生命周期、知识检索、语义索引、企业 ACL、来源追溯与治理。

状态与权威：上下文与记忆资产；不替代事实库、执行状态或 Agent Session。

IDP MCP Infrastructure

独立标准 MCP 接入与治理产品

MCP Server/Client 双向角色接口、Server/Tool Registry、发现、授权、协议路由、策略与审计。

状态与权威：MCP 连接与治理元数据；不是通用跨协议 API Gateway 或任务编排引擎。

03 · 典型协作路径

轻量 Agent 场景与企业级可靠执行场景采用不同的集成深度。调用方可以是 Workspace、外部 API 或业务事件，不强制由 Workspace 发起；可靠执行任务可以跳过 HOST 直接进入 EER，MCP Infrastructure 也是可选的协议接入路径。

04 · 数据与状态权威边界

系统具有权威的数据 / 状态不得替代的部分
Workspace工作对象视图、应用安装与协作、工作 Inbox业务领域事务、Agent Harness、EER Checkpoint
HOSTAgentRun、Session、模型/工具调用与执行协调状态正式企业业务任务的可靠执行状态
EERGoal/Task/Plan/Execution、Checkpoint、审批、证据、验证订单、财务账本、库存等领域主数据的最终提交
CMIContextPackage、记忆索引、检索来源与生命周期业务事实系统、AgentRun、EER Checkpoint
MCP InfrastructureMCP 服务注册、能力发现、连接、授权与审计通用 AI Gateway、Agent Runtime、业务工作流
企业业务系统订单、库存、运单、会计账本、客户数据等不应被 CMI 记忆或 Agent 文本写入绕过事务规则

特别说明：MCP Infrastructure 可以包含标准 MCP Client / Server 的双向协议接口及内部治理路由，但不等于另行规划的通用 IDP Gateway。后者不属于当前已锁定的五大核心系统，也不是 MCP 的强制依赖。

采用 Polyrepo：五个可独立交付的运行仓库，另有一个产品集成仓和一个公开契约仓。它们不是七个必须同时运行的微服务。

部署原则

独立构建、升级、回滚、状态存储和发布版本；客户可根据场景选择单模块或联合部署。不得通过跨库直连、跨仓内部代码引用或共享私有数据库表制造隐性强依赖。

技术路线（工程方向）

总体优先 Go 服务端、TypeScript/React 客户端；Python 按需用于 AI Harness 与记忆处理 Worker。具体语言仍以各独立仓库已经确认的技术基线及实测结果为准，不因为平台整合而重写既有可用代码。

06 · 架构审查结论

既定产品基线已经清晰：Workspace 是企业工作入口；HOST 是智能体运行中枢；EER 是可靠执行权威；CMI 是上下文与记忆基础设施；MCP Infrastructure 是标准工具连接与治理基础设施。 在它们之上形成统一企业体验，在它们之外保持领域系统的业务事实权威。

本图是依据当前确认的 TELOS 架构方向整理的说明性设计制品，不代表五个子系统已完成生产部署或跨系统联调验收。品牌图形沿用已有锁定 TELOS 矢量字形。
