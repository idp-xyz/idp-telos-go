五大架构单元

其中 Workspace、HOST、CMI、MCP Infrastructure 为四大独立子系统；EER 是独立核心运行时，不应与 HOST 混合。

设计原则：权威归属唯一；数据可以通过受控接口访问，但其他系统不能私自复制或改变源系统的权威状态。

      三种核心场景的执行语义

      SCENARIO 01普通问答 / 知识检索

      Workspace → HOST ↔ CMI → 用户。无需强制进入 EER 长任务，遵循受控只读权限。

      SCENARIO 02企业级可靠执行

      Workspace → HOST → EER；EER 按需调用 HOST / CMI / MCP，领域系统执行最终业务提交，Verifier 验收。

      SCENARIO 03跨 Agent 协作

      HOST 使用 A2A 委派跨运行时 Agent。EER 对企业任务委派关系、执行状态和结果负责。

      协议与可靠执行边界

      协议 / 机制主要归属作用禁止混淆
      AG-UI / Host APIWorkspace ↔ HOST用户交互、消息及运行状态呈现不代替企业执行状态机
      A2AHOST Federation AdapterAgent 能力发现和任务委派不共享内部记忆权威
      MCP 2026-07-28 Modern StatelessMCP Infrastructure标准连接、工具调用治理与发现Stateless 不等于 EER 无状态
      Execution API / Event FabricEER计划、幂等、Outbox / Inbox、重试与补偿不得交由 HOST Session 代管
      Context APICMI授权上下文解析、知识与记忆治理记忆不能覆盖实时业务事实
      安全横切要求：身份原始权威由 Enterprise IAM / IdP 提供；各边界独立执行身份校验与最小权限；防止 Prompt Injection、记忆污染、Skill 供应链与跨租户越权。
