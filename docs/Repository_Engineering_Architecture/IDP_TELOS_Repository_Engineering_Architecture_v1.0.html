Repository & Engineering Architecture Specification

IDP TELOS
企业级工程仓库与交付架构

为 AI-Native Enterprise Execution Platform 建立长期可演进的工程组织基线。将产品总工程、五个独立运行单元与跨系统契约治理明确分离，同时通过统一集成、版本组合、质量门禁和部署配置形成可交付的平台产品。

文档版本 v1.0 / 建议架构模式 Polyrepo + Integration Repository独立运行单元 5建议 Git 仓库 7适用 SaaS · Private Cloud · On-Prem
Engineering Scope07独立 Git 仓库：5 个运行单元 + 集成总仓 + 契约仓
Runtime Boundaries05Workspace / HOST / EER / CMI / MCP Infrastructure
Core Authority01EER 掌握企业执行状态，业务系统掌握领域事务
Delivery Model03SaaS / 私有云 / 本地部署产品化交付
核心裁决：idp-telos 是集成与交付仓库，不是聚合五套源码的超级仓库；五个运行单元拥有独立 Git、构建、版本、存储与部署生命周期。idp-contracts 为公开跨系统契约提供版本化共享发布，不持有其他系统的业务状态。

03 / OWNERSHIP MODEL
职责与状态权威归属

  
采用 One Source of Truth 原则：每类关键对象只有一个权威所有者，展示、查询、缓存与事件投影都不得成为第二份业务事实。

  
数据 / 能力权威仓库与系统其他参与方禁止的混淆

  
UI / View StateWorkspaceHOST / EER 提供数据不可将 UI 缓存当作审批记录

  
AgentDefinition / AgentRun / SessionHOSTEER 引用 agent_run_id不可用 AgentRun 替代业务 Execution

  
Skill Package / Agent ConfigurationHOSTEER 固定已批准版本不可由 MCP Registry 代管 Skill 定义

  
Goal / Task / Plan / ExecutionEERHOST 生成候选计划不可由 HOST 持有最终任务状态

  
Checkpoint / Retry / Approval / EvidenceEERWorkspace 展示，CMI 提炼经验不可把执行 Checkpoint 写入 CMI 记忆

  
Memory / ContextPackage / Knowledge IndexCMIHOST / EER 授权调用不可将记忆取代实时领域事实

  
MCP Tool / Server RegistryMCP InfrastructureHOST / EER 发现和使用不能代替业务 API 的权威合同

  
MCP Connection Policy / Invocation AuditMCP Infrastructure平台统一关联 Trace不能绕过领域业务权限

  
订单 / 库存 / 运单 / 账务Brant / PRISM / Parcel 等领域系统EER 发起有授权的业务命令Agent 或 CMI 不得自行提交事务

  
平台版本组合 / 部署规格idp-telos引用各仓库发布件不能覆盖组件自己的版本号

  
公开共享 Schema 及兼容治理idp-contracts（分系统领域所有权）生产者拥有语义，平台审核兼容性共享仓库不等于统一领域模型

  

 


 

  
04 / DEPENDENCY BOUNDARY
代码依赖与服务调用的严格边界

  
将“源码依赖”与“运行时服务通信”分开治理。跨仓库必须经过公开发布接口，不得因为同在一个开发目录就建立编译时内部依赖。

  
✓ 允许的关系
  • Workspace → HOST：Agent API / AG-UI
  • Workspace → EER：Task / Approval 公共 API
  • HOST ↔ EER：版本化 Execution / AgentRun API 与事件
  • HOST / EER → CMI：授权 Context API
  • HOST / EER → MCP Infrastructure：标准 MCP 或经批准的工具 API
  • EER → 领域系统：领域 Command API，领域端再次授权
  • 消费版本化 SDK / Schema；携带 W3C Trace Context 及稳定关联 ID
× 明确禁止
  • 跨仓库引用其他服务的 internal/ 包或数据库表
  • 在 idp-telos 复制五套可执行服务源代码
  • 用 CMI 的记忆存储替换 EER 的 Checkpoint
  • 用 MCP Gateway 实现独立的业务任务状态机
  • 通过平台总仓库同步修改多个系统的数据库 Schema
  • 运行时直接使用本地 go.work 中未发布的依赖
  • 将密钥、客户生产配置或个人数据提交到 Git

  
典型执行链路（不是所有会话都需要进入 EER）
01 / INITIATEWorkspace / API
业务目标和身份上下文进入平台
02 / PLANHOST + EER
HOST 辅助推理；EER 校验并固化正式计划
03 / CONTEXTCMI
提供授权、来源明确的 Context Package
04 / EXECUTEEER + MCP
幂等、审批、工具调用与可靠恢复
05 / COMMITDomain System
领域业务系统最终提交与验收回传
普通对话与只读检索允许 Workspace → HOST → CMI，不要求每次生成 EER 长任务。

 


 

  
05 / CONTRACT FIRST
跨系统契约与兼容治理

07 / DELIVERY OPTIONS
面向全球企业的部署与数据隔离

  
同一套组件和公开契约支持不同交付形态。多租户、数据驻留、监管要求以及模型接入策略属于部署差异，不应倒逼核心系统形成多套源码。

  

   
PROFILE A
SaaS
区域化部署；租户身份、逻辑隔离、按租户配额；统一 CI/CD 与分批发布。
重点：租户隔离验证、数据驻留策略、控制面与数据面隔离。

   
PROFILE B
Private Cloud
客户专用云环境；专属网络、密钥服务、数据库与模型接入端点。
重点：VPC 权限、镜像供应链、升级与运维责任。

   
PROFILE C
On-Premises
离线或受限网络；私有制品仓库、受控更新、可选本地推理环境。
重点：可重复安装、离线授权、密钥轮转和容灾恢复。

  

  
关键边界：允许早期共享 PostgreSQL 实例，但每个服务必须拥有独立 Schema 或数据库、独立迁移与凭证。平台集成层不得直接执行其他服务的数据迁移脚本。所有 Region、Tenant、PII 处理策略应明确并可审核。

 


 

  
08 / GLOBAL ENGINEERING STANDARDS
安全、可观测与贡献规则

  

   
Zero Trust & Agent Security
服务身份与用户委派分离；每个业务命令都需策略执行点校验。工具权限不能仅依赖模型指令。对 Tool Result、Retrieved Content、Memory、Skill Package 都按不可信输入处理，避免 Prompt Injection 和记忆污染。
密钥通过 Vault/KMS 或同等级方案注入；Skill 包应支持版本固定、来源验证和回滚。

   
Observability & Evidence
统一 trace_id / correlation_id / tenant_id 与 execution_id 关联，遵循 W3C Trace Context。敏感信息不写入 Trace Baggage；审计事件应保存来源、主体、授权结果与证据引用。
最低观测对象：任务成功率、恢复率、工具执行失败、策略拒绝、成本与端到端耗时。

  

  
Repository Governance
所有仓库具有 CODEOWNERS、分支保护、依赖更新策略、SECURITY.md、ADR 和变更日志。对公开接口修改必须评审兼容性及迁移说明，严禁强制跨仓库原子提交作为日常发布机制。
Developer Experience
开发机以并列仓库方式工作；go.work 仅作为可选本地协作机制。正式 CI/Release 依赖独立发布的模块版本；使用模拟服务验证“脱离其他仓库仍可运行”。
